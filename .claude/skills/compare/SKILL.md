# AI 中转站比价计算

用户已在对话上下文中提供了某个 AI 中转站的定价信息（截图或文字）。你需要按以下步骤完成比价分析。

## 第一步：提取定价信息

从对话上下文中提取以下信息。如果信息不完整，向用户追问：

- **中转站名称**
- **套餐名称**（如有）
- **产品类型**：零售余额型 or 套餐额度型
- **充值金额**（人民币）及到账单位（美元余额/积分/credit）和数量
- **模型名称**
- **扣费规则**：input / output / cached input 分别扣多少平台单位（每 1M token）
- **如果是积分池型**：积分上限、恢复速度、每日重置规则

如果截图中有多个套餐，逐个分析，每个套餐单独成行。

## 第二步：查官方价格

读取项目中的 `官方模型价格表.csv`：

!`cat 官方模型价格表.csv`

找到对应模型的官方 input / output / cached_input 单价（美元/1M token）。

**注意**：不要混模型。GPT-5.4 用 GPT-5.4 的价格，不要用 GPT-5.5 的。如果价格表中没有该模型，告知用户并请求补充。

## 第三步：分类计算

### A. 零售余额型

适用于：充值人民币 → 到账美元余额或积分 → 按 token 消耗扣费。

```
平台单位成本 = 充值人民币 ÷ 到账平台单位数
```

分三个场景计算：

**纯 input 场景**：
```
平台消耗（平台单位）= 平台 input 扣费/1M × 使用量M
官方等值（$）= 官方 input 单价 × 使用量M
用户实付（¥）= 平台消耗 × 平台单位成本
¥/官方$1 = 用户实付 ÷ 官方等值
```

**纯 output 场景**：同上，换成 output 单价。

**80/20 混合场景**：
```
官方等值 = 0.8 × 官方input单价 + 0.2 × 官方output单价
平台消耗 = 0.8 × 平台input扣费 + 0.2 × 平台output扣费
¥/官方$1 = (平台消耗 × 平台单位成本) ÷ 官方等值
```

### B. 套餐额度型

#### B1. 固定美元额度（如"¥20 买 $200 额度"）

```
¥/官方$1 = 实付人民币 ÷ 美元额度
```

前提假设：该美元额度按官方 API 价格扣费。如果不确定，标注风险。

#### B2. 固定积分总量（如"$15 买 270000 积分"）

先把积分换算成 token：
```
可用 input token = 总积分 ÷ 平台input积分单价/1M × 1M
可用 output token = 总积分 ÷ 平台output积分单价/1M × 1M
```

再算官方等值美元：
```
纯input官方等值 = 可用input token ÷ 1M × 官方input单价
纯output官方等值 = 可用output token ÷ 1M × 官方output单价
```

最后：
```
¥/官方$1 = 用户实付人民币 ÷ 官方等值美元
```

分别算纯 input、纯 output、80/20 混合三个口径。

#### B3. 积分池 + 恢复（如"9000 上限 + 260/小时恢复 + 每日重置"）

不能只看一次性积分，要算 30 天可消费总量：

- **保守**：每小时恢复 × 24 × 30，不算每日重置
- **常规**：保守 + 每日重置一次 × 30
- **上限**：保守 + 每日重置 + 假设积分始终被消耗完

分三个口径都要算出 ¥/官方$1。

## 第四步：汇总输出

用表格展示计算结果，格式如下：

```
| 场景 | 平台可用量 | 官方等值($) | 用户实付(¥) | ¥/官方$1 | 评价 |
```

评价参照以下标准：
- > ¥7：比官方还贵
- ¥3～¥7：小折扣，看稳定性
- ¥1～¥3：明显便宜，可作备用
- ¥0.3～¥1：很便宜，重点看风险
- ¥0.1～¥0.3：极便宜，默认高风险
- < ¥0.1：优先怀疑可持续性和真实性

同时列出关键假设和风险点（如：是否确认按官方价扣费、是否有 cached input 优惠、扣费明细是否透明等）。

## 第五步：写入结果

确认用户对计算结果无异议后，将结果追加到 `比价结果数据.csv`。

读取当前 CSV 文件，在末尾追加新行。每个套餐/口径一行，字段为：
```
对象,原定价/原规则,折算前提,折合官方用量,用户实付,折合定价/官方$1
```

- **折合定价/官方$1**：使用 80/20 混合场景的值（最贴近实际使用）
- 如果有多个口径（保守/常规/上限），每个口径分别一行
- 金额中包含逗号的用双引号包裹

写入后告知用户已更新。
